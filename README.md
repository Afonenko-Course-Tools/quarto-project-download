# Скачивание материалов проекта Quarto

`project-download` создаёт воспроизводимые ZIP-архивы явно перечисленных
материалов: наборов данных, демонстраций, карточек семинара или стартовых проектов.
Расширение работает без учебной модели, адаптеров оценивания и CUE.

## Подключение

```sh
quarto add Afonenko-Course-Tools/quarto-project-download
```

Установка пассивна. Подключите фильтр, обработчики и ресурсы явно:

```yaml
project:
  type: website
  output-dir: _site
  resources: ["!materials/**"]
  pre-render: _extensions/Afonenko-Course-Tools/project-download/entrypoints/pre.ts
  post-render: _extensions/Afonenko-Course-Tools/project-download/entrypoints/post.ts
filters: [project-download]
project-download:
  resources:
    seminar-data:
      path: /materials/observations
      include: ["**/*.csv", "**/*.md"]
      exclude: ["**/draft-*", "private/**"]
```

```qmd
{{< project-download seminar-data text="Скачать данные семинара" >}}
```

Пути обработчиков соответствуют установке из GitHub; локальная установка может
создавать каталог без владельца. Пример `examples/materials` использует локальную
установку `quarto add ../..`.

## Контракт

| Поле ресурса | Значение |
|---|---|
| `path` | Обязательный каталог относительно корня текущего проекта; начальный `/` обозначает этот корень |
| `include` | Список шаблонов glob; по умолчанию `**/*` |
| `exclude` | Дополнительные шаблоны исключения относительно `path` |
| `profiles` | Необязательный список профилей, в которых ресурс разрешён |
| `gitignore` | Применение `.gitignore`, по умолчанию `true` |

ID состоит из латинских строчных букв, цифр и дефисов; первый символ — буква
или цифра. Регистрируемые параметры определяются в `domain/config.ts`.
Неизвестные поля отклоняются. Ссылка на необъявленный ресурс — ошибка сборки.

Архив создаётся только при наличии видимого shortcode после отбора содержимого
Quarto. Условия видимости задаются стандартным `.content-visible when-profile`,
либо кратким условием Core, если он отдельно подключён. `profiles` проверяет
разрешённость уже видимой ссылки, а не автоматически скрывает её.

```qmd
::: {.content-visible when-profile="full"}
{{< project-download teacher-notes >}}
:::
```

Материалы с ограничениями следует исключать из обычного копирования Quarto
через `project.resources`. Архивирование само по себе не меняет правила
публикации исходных каталогов другими расширениями.

## Состав архива и воспроизводимость

Публикуются только обычные файлы выбранного каталога после отбора. Путь не может
выходить из проекта; символические ссылки отклоняются. Встроенные исключения
собраны в `DEFAULT_EXCLUDES`: служебные каталоги Git, Quarto, IDE и сборки,
кэши, прежние результаты и скомпилированные файлы. Авторские исключения дополняют их.

Для точной обработки вложенных `.gitignore`, отрицаний и исключений каталогов
используется Git с временным изолированным индексом. Правила внешнего репозитория,
пользовательский файл исключений и его индекс не влияют на результат. Исходный
каталог может быть обычной копией без `.git`. Нужен Git в `PATH`; при
`gitignore: false` он не вызывается.

ZIP использует STORE, UTF-8, фиксированную дату и сортировку по именам. Отдельный
архиватор не нужен. Очень большие ZIP64 не поддерживаются; архив формируется
в памяти, поэтому этот механизм предназначен для учебных материалов умеренного
объёма. Готовые большие файлы лучше публиковать отдельными ресурсами.

## Обработчики и владение результатами

1. `pre.ts` очищает предыдущие заявки и только архивы из собственного манифеста.
2. Фильтр после Quarto сохраняет заявки видимых документов.
3. `post.ts` формирует архивы `_downloads/<id>.zip` внутри текущего каталога вывода.

Манифест `.project-download-manifest.json` описывает файлы расширения.
Посторонние архивы не удаляются; конфликт имени отклоняется. Ошибка рендера после
`pre.ts` не оставляет старые архивы прежнего профиля. `--output-dir` координатора
учитывается через `QUARTO_PROJECT_OUTPUT_DIR`, включая каталог вне исходников.
Проект должен подключать оба обработчика; неполный рендер одного документа не
заменяет полную пересборку публикации.

В Git хранятся исходники и конфигурация. `_generated/`, `_downloads/` и результаты
рендера исключаются. Предварительная сборка не изменяет материалы.

## Необязательная связь с Core

Для уже существующей разметки `{{< project-download exr-example >}}` доступен
явный мост:

```yaml
project-download:
  course-model: true
  resources: {}
```

Если ID не объявлен непосредственно, мост ищет видимое задание с тем же ID
и исходным документом в проверенном `_generated/course-spec/course.json` и
архивирует только `<project>/student`. Он не включает соседние `reference` и
закрытые `tests`. Явный ресурс имеет приоритет.

В этом режиме `course-core` должен выполняться до `project-download`, а его
`post.ts` — раньше обработчика скачивания. Только мост требует готовой проверенной
модели Core; обычные ресурсы от неё не зависят. Рекомендуемый вариант для новых
проектов — явно объявленные ресурсы, которые подходят любому предмету курса.

## Архитектура и проверки

| Каталог пакета | Ответственность |
|---|---|
| `domain` | Контракт ресурсов и детерминированный формат ZIP |
| `application` | Разрешение заявок и сценарий публикации через порты |
| `infrastructure` | Файлы, Git, Quarto, манифест и необязательное чтение модели Core |
| `entrypoints` | Явные обработчики сборки |

```sh
quarto run tests/archive.ts
quarto run tests/render.ts
```

Проверяются `.gitignore` без репозитория и внутри игнорируемой копии, границы
путей, символические ссылки, детерминизм, кириллица, профильные ограничения,
изоляция очистки и реальные сборки Quarto без CUE.
