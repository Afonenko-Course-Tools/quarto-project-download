# Скачивание материалов проекта Quarto

`project-download` создаёт воспроизводимые ZIP-архивы явно перечисленных
материалов: наборов данных, демонстраций, карточек семинара или стартовых проектов.
Расширение работает без учебной модели, адаптеров оценивания и CUE. Его результат — архив выбранных файлов; компиляция стартового проекта, проверка программы и доставка задания в LMS выполняются другими инструментами.

## Подключение

```sh
quarto add Afonenko-Course-Tools/quarto-project-download@v1.1.0
```

Установка пассивна. Подключите фильтр, обработчики и ресурсы явно:

```yaml
project:
  type: website
  output-dir: _site
  resources: ["!materials/**"]
  pre-render: _extensions/Afonenko-Course-Tools/project-download/entrypoints/pre.ts
  post-render: _extensions/Afonenko-Course-Tools/project-download/entrypoints/post.ts
filters: [project-download]
project-download:
  resources:
    seminar-data:
      path: /materials/observations
      include: ["**/*.csv", "**/*.md"]
      exclude: ["**/draft-*", "private/**"]
```

```qmd
{{< project-download seminar-data text="Скачать данные семинара" >}}
```

Пути обработчиков соответствуют установке из GitHub; локальная установка может
создавать каталог без проекта. Пример `examples/materials` использует локальную
установку `quarto add ../..`.

## Контракт

| Поле ресурса | Значение |
|---|---|
| `path` | Обязательный каталог относительно корня текущего проекта; начальный `/` обозначает этот корень |
| `include` | Список шаблонов glob; по умолчанию `**/*` |
| `exclude` | Дополнительные шаблоны исключения относительно `path` |
| `profiles` | Необязательный список профилей, в которых ресурс разрешён |
| `gitignore` | Применение `.gitignore`, по умолчанию `true` |

ID состоит из латинских строчных букв, цифр и дефисов; первый символ — буква
или цифра. Регистрируемые параметры определяются в `domain/config.ts`.
Неизвестные поля отклоняются. Ссылка на необъявленный ресурс — ошибка сборки.

Архив создаётся только при наличии видимого shortcode после отбора содержимого
Quarto. Условия видимости задаются стандартным `.content-visible when-profile`,
либо кратким условием Core, если он отдельно подключён. `profiles` проверяет
разрешённость уже видимой ссылки, а не автоматически скрывает её.

```qmd
::: {.content-visible when-profile="full"}
{{< project-download teacher-notes >}}
:::
```

Материалы с ограничениями следует исключать из обычного копирования Quarto
через `project.resources`. Архивирование само по себе не меняет правила
публикации исходных каталогов другими расширениями.

## Стартовые проекты и закрытые материалы

Для проекта с каталогами `student/`, `reference/` и `tests/` выбирайте в
`resources.<id>.path` именно `student/`, а не весь родительский проект. Поля
`include`/`exclude` дополнительно ограничивают состав; одна ссылка на проект
в учебной модели не даёт разрешения выдавать авторское решение и закрытые тесты.

Явно выбранные публичные материалы могут содержать исходники стартовой программы
на Python, shell, TypeScript и других языках, её YAML/TOML-конфигурацию и README.
Расширение файла само по себе не определяет закрытый материал. Учебные входы
Quarto (`.qmd`, `.rmd`, `.ipynb` и текущие входные документы), `_quarto*`,
`_metadata.yml`, подключённые build/filter scripts, служебные каталоги и
`reference`/`solution` отклоняются. Для известных проектов заданий закрытые
корневые `tests/`, `closed-tests/` и служебный `check.sh` также не выдаются;
публичные тесты и скрипты внутри `student/` остаются материалами задания.
Фильтры с объявлением `filters: [{path: ...}]` защищаются так же, как строковые
пути. Core передаёт проверенные пути проектов до student projection как
`resources.rawProjectRoots`, поэтому удаление скрытого задания из публичной
модели не открывает его закрытые тесты или служебный `check.sh` для скачивания.
Если README служит файлом проекта для
скачивания, исключите его из входов render, например явным `project.render`.

Открытые и преподавательские ресурсы можно объявить отдельно и ограничить через
`profiles`. Выбор профиля не предоставляет права доступа на сервере и не делает
секретными исходники публичного Git. В составном курсе проверяйте содержимое
архивов обоих профилей вместе с фактически опубликованными страницами.

## Состав архива и воспроизводимость

Публикуются только обычные файлы выбранного каталога после отбора. Путь не может
выходить из проекта; символические ссылки отклоняются. Встроенные исключения
собраны в `DEFAULT_EXCLUDES`: служебные каталоги Git, Quarto, IDE и сборки,
кэши, прежние результаты и скомпилированные файлы. Авторские исключения дополняют их.

Для точной обработки вложенных `.gitignore`, отрицаний и исключений каталогов
используется Git с временным изолированным индексом. Правила внешнего репозитория,
пользовательский файл исключений и его индекс не влияют на результат. Исходный
каталог может быть обычной копией без `.git`. Нужен Git в `PATH`; при
`gitignore: false` он не вызывается.

ZIP использует STORE, UTF-8, фиксированную дату и сортировку по именам. Отдельный
архиватор не нужен. Очень большие ZIP64 не поддерживаются; архив формируется
в памяти, поэтому этот механизм предназначен для учебных материалов умеренного
объёма. Готовые большие файлы лучше публиковать отдельными ресурсами.

## Обработчики и владение результатами

1. `pre.ts` очищает предыдущие заявки и только архивы из собственного манифеста.
2. Фильтр после Quarto сохраняет заявки видимых документов.
3. `post.ts` формирует архивы `_downloads/<id>.zip` внутри текущего каталога вывода.

Манифест `.project-download-manifest.json` описывает файлы расширения.
Посторонние архивы не удаляются; конфликт имени отклоняется. Ошибка рендера после
`pre.ts` не оставляет старые архивы прежнего профиля. `--output-dir` координатора
учитывается через `QUARTO_PROJECT_OUTPUT_DIR`, включая каталог вне исходников.
Проект должен подключать оба обработчика; неполный рендер одного документа не
заменяет полную пересборку публикации.

В Git хранятся исходники и конфигурация. `_generated/`, `_downloads/` и результаты
рендера исключаются. Предварительная сборка не изменяет материалы.

## Публичное владение временными заявками

Координатор нативных сборок импортирует поддерживаемый модуль
`_extensions/project-download/ownership.ts` из установленного расширения.
Текущий контракт один:

```ts
export interface OwnedRequestState {
  protocol: 1;
  root: string;
  directory: string;
  files: {
    path: string;
    source: string;
    resources: string[];
    sha256: string;
  }[];
}
export function inspectOwnedRequests(
  root: string, sources: string[]
): Promise<OwnedRequestState>;
export function clearOwnedRequests(
  root: string, sources: string[]
): Promise<void>;
```

`root` — канонический абсолютный путь проекта; `sources` — уже проверенные
координатором входные документы этого проекта, в канонических относительных
путях файловой системы. Расширение возвращает абсолютные канонические `root`,
`directory` и `files[].path`. `directory` задаёт точную область изменяемых заявок,
даже когда она отсутствует; в этом случае `files` пуст. Каждый элемент содержит
источник, ID ресурсов и SHA-256 точных текущих байтов заявки. Пустая заявка
документа без видимого shortcode также входит в снимок.

Вызывайте `inspectOwnedRequests` после ожидаемого завершения нативного дочернего
процесса: hooks и фильтры этого процесса
должны закончиться перед чтением. Сохраните нужный снимок, затем вызывайте
`clearOwnedRequests` для очистки той же последовательной попытки. Не запускайте
запись заявок, чтение и очистку одновременно. Снимок не является транзакционной
блокировкой. Перед удалением расширение повторно проверяет всю собственную
область. Оно удаляет только заявки и их каталог, сохраняя родителей, соседние
файлы и опубликованные архивы.

Оба вызова отклоняют ссылки в корне, его родителях, каталогах области и файлах,
включая ссылки без цели; специальные файлы, вложенные каталоги и посторонние
записи; повреждённые или дополнительные поля заявки; неизвестный источник,
несоответствие имени источнику и недопустимый ID ресурса. Ошибка проверки
предшествует очистке. Внутренние имена файлов и JSON транспорта принадлежат
расширению: потребитель использует этот API и не воспроизводит их алгоритм.

Заявки — временное состояние конкретной сборки, а не авторская конфигурация
и не публикуемый результат. Они содержат пути исходных документов и ID ресурсов,
видимых в выбранном профиле, включая ресурсы `full`. Координатор отвечает за
удаление своих сохранённых снимков и за исключение временной области из выдачи.
Этот API не отбирает содержимое профиля и не меняет правила доступности архивов.
Обычное подключение shortcode, фильтра и обработчиков остаётся прежним.

## Необязательная связь с Core

Для уже существующей разметки `{{< project-download exr-example >}}` доступен
явный мост:

```yaml
project-download:
  course-model: true
  resources: {}
```

Если ID не объявлен непосредственно, мост получает задание с тем же ID и источником из текущего NativeRun Core и архивирует только `<project>/student`. При full используется сохранённая публичная проекция `body.publicExercises`. `course.json` не читается. Явный ресурс имеет приоритет, но также проходит публичную resource policy Core, включая full: hidden-only файлы, учебные входы, служебные файлы и отсутствующие generated ресурсы отклоняются. Мост передаёт явно выбранные файлы как публичный payload с перечнем известных учебных и build-входов; исходники программы из `student/` не считаются учебным исходником по одному расширению.

Установка Core сама по себе не активирует мост. Если Core обработал текущий AST, его публичная resource policy применяется и при `course-model: false`. Runtime находит Core рядом с установленным Download, включая каталог владельца GitHub.

Подключите `course-core` перед `project-download`, native Core pre-hook перед Download pre-hook и Core post-hook перед Download post-hook. После успешного native процесса координатор может вызвать `finish(root, {run, evaluateResources})` с явным текущим NativeRun и публичным API Core. Проверяется совпадение project/output и наличие текущего DocumentResult для каждой заявки. Старые страницы выбранного проекта не становятся текущим inventory.

Обычные явно объявленные ресурсы работают без Core/CUE и сохраняют собственные ограничения исходных/служебных каталогов. Не помещайте закрытые материалы в публичный каталог. Каждый native pre-hook очищает только выбранный output архивов и текущие заявки; другие audience outputs и native caches сохраняются.

## Архитектура и проверки

| Каталог пакета | Ответственность |
|---|---|
| `domain` | Контракт ресурсов и детерминированный формат ZIP |
| `application` | Разрешение заявок и сценарий публикации через порты |
| `infrastructure` | Файлы, Git, Quarto, манифест и явный текущий NativeRun и resource policy Core |
| `entrypoints` | Явные обработчики сборки |

```sh
quarto run tests/archive.ts
quarto run tests/render.ts
quarto run tests/ownership.ts
```

Проверяются `.gitignore` без репозитория и внутри игнорируемой копии, границы
путей, символические ссылки, детерминизм, кириллица, профильные ограничения,
изоляция очистки и реальные сборки Quarto без CUE.
Публичный API дополнительно проверяется на заявках нативно установленного
расширения, пустых результатов, повреждённых и чужих записях, ссылках и точных SHA-256.

Native installed acceptance additionally runs `CORE=../quarto-course quarto run tests/native.ts` and `CORE=../quarto-course quarto run tests/native-installed.ts` on Quarto 1.10.18/1.11.5, CUE 0.17.1. It covers selected-document freshness, student/full/student isolation, hidden-only ZIP resources and missing current resources.

## Версии и обновление

Релиз `v1.1.0` соответствует версии в `_extension.yml`. Устанавливайте явный тег, как в команде выше, и сохраняйте установленные файлы `_extensions` в Git курса. Для обновления установите следующий опубликованный тег через `quarto add`, проверьте diff и выполните проверки курса. Опубликованные теги неизменяемы: исправления получают новую версию и новый тег.

## Сообщения и исправление

[Справочник диагностики](docs/diagnostics.md) связывает устойчивый ID с доступным
контекстом и действием автора. Ошибки Core и внешних инструментов сохраняют
свой ID и исходный вывод. Публичную сборку проверяйте штатным
`quarto render --fail-if-warnings`; отдельного warning-режима расширения нет.

Локальная проверка `CORE=/absolute/path/to/quarto-course bash tools/check.sh`
включает контекст собственных диагностик, foreign CLI-потоки, ZIP, профили,
владение заявками и установленные namespaced/plain/active подключения.
Успешный рендер не выполняет стартовый проект и не доставляет его в LMS.
